summary with links. Render the complete briefing below: every numbered
section, in order, in one answer. Length is expected. A reader should

## Standing directives

- **Read before you write.** Every number, count, table, filename, and
  status in your briefing comes from files read at tour time — above all
  `../02-LEADS/REPORT.md` and `../STATE.md`, plus directory listings.
  This file deliberately contains no numbers; the OS changes daily.
- **Embed, don't link.** Reproduce the tables in the answer itself. A
  link is a supplement, never a substitute.
- **Never invent.** If a detail is not in a file in this OS — dialer
  interface specifics, recommended starting counties, outcome menus,
  schedules — it does not appear in the tour. No filler, no guesses.
- **Strictly read-only.** A tour never modifies, renames, or creates
  anything. If the user asks for changes, note that changes go through
  the owner, and continue.
- Plain language throughout. Every term of art gets a one-line
  explanation the first time it appears.

## The briefing template

### 1. What this is
Three or four sentences: an operating system for a web-design company's
lead generation. It finds small service businesses, verifies them,
classifies the state of their web presence, and produces ready-to-call
files for the Teleblast dialer. A human makes the calls; the OS does
everything before and after them (tracking).

### 2. The numbers, right now
Read `../02-LEADS/REPORT.md` and `../STATE.md`, then embed:
- The headline: total callable leads, Class A vs Class B, batch count,
  and how much has been called so far.
- The class-by-state totals as a table.
- The county tables (rank, county, leads, batches, progress) for each
  class/state — reproduce them, complete. If the report is long, the
  briefing is long; that is correct.
- Anything STATE.md flags as current (campaign, reserved territory,
  pending decisions).

### 3. LEADS, dissected (this is the heart — be thorough)
- The path anatomy, walked with one REAL example from the tree, from
  `02-LEADS/` all the way down to an actual batch file that exists.
- What Class A and Class B mean, precisely.
- `00-MASTER` vs `BATCHES`: master is the county's full list and is
  never loaded into the dialer; batches (at most 100 leads, best leads
  first) are the loading unit. Batch-01 of any county is its strongest
  leads.
- County folder numbering = rank by lead count within that state.
- **Decode the Notes column field by field** using a real row from a
  real batch file: the optional origin tag, the priority marker (P1 =
  Class A with social/directory presence only, P2 = Class A with no web
  presence, P3 = Class A with a broken or parked site, P4 = Class B),
  the class label, the plain-language reason it qualified, and the
  website URL when one exists. Explain how a caller uses each piece.
- The other Teleblast columns and which are intentionally blank.
- `TRACKER.csv`: one row per batch; the lifecycle
  `untouched → loaded → called → done`; what gets recorded (dates,
  bookings, notes). `REPORT.md` is the generated, human-readable view of
  the tracker — regenerated by a tool, never edited by hand.

### 4. The daily workflow (part of the tour, not a follow-up)
Exactly these steps, no invented additions:
1. Pick a county and take its next unused batch file from `BATCHES`.
2. Load that CSV into Teleblast (never the master).
3. Call top-down; the file is already sorted best-first. Scripts live in
   `01-PLAYBOOK/SCRIPTS/`.
4. Afterward, report what happened (which batch, calls made, bookings,
   do-not-calls) to the OS operator — an AI session in this workspace —
   which updates the tracker and registry and regenerates the report.
   Tracker, registry, and report are never edited by hand.

### 5. PLAYBOOK
List the actual files currently in `SCRIPTS/`, `CALLS/`, and
`TRAINING/` (names, not categories), with one line on each subfolder's
rule: scripts are living and versioned; calls are add-only and never
edited; training is reference material.

### 6. The machinery, honestly but briefly
One paragraph: two independent acquisition engines (V1 browser lane,
V2 terminal lane — V2 is the production workhorse) discover and classify
businesses; SHIPPING is the only bridge from engine output into LEADS,
and its registry permanently remembers every lead ever shipped, making
double-shipping and double-dialing structurally impossible. Deep dive:
`03-LEAD-SOURCING-ENGINE/README.md`.

### 7. SKILLS and ARCHIVE
One line each: SKILLS holds trigger-phrase instruction documents (this
tour is one); ARCHIVE is the frozen museum — read-only artifacts, never
operated.

### 8. The laws, in plain language
Translate the Laws section of `../AGENTS.md` faithfully — including:
only SHIPPING ships; the registry only grows and do-not-call is forever;
classes require evidence and inconclusive is never Class A; blocks stop
scraping; funnels are reported honestly; reserved territory never ships;
LEADS is regenerable output, never hand-edited.

### 9. Where to look for what
A short pointer list: current status → `STATE.md`; live numbers →
`02-LEADS/REPORT.md`; a county's calling file → its `BATCHES/` folder;
scripts → `01-PLAYBOOK/SCRIPTS/`; machinery →
`03-LEAD-SOURCING-ENGINE/README.md`; the constitution → `AGENTS.md`.
